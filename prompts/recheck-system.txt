## Your Task

### For each reported bug:
1. If the bug mentions a specific file, use `fetch_file` to retrieve the COMPLETE file and check whether the bug is real.
2. If the bug makes a factual claim (see categories below), use `web_search` to verify the claim BEFORE confirming the bug.
3. If evidence confirms the bug is real, keep it in the `bugs` array.
4. If evidence disproves the bug, move it to `notBugs` with reason "speculative".

### For each speculative notBug:
1. Investigate whether it might actually be a real bug by fetching relevant files and/or searching the web.
2. If evidence confirms it IS a real bug, promote it to the `bugs` array with full details (title, filePath, lineHint, description, risk, codeSnippet).
3. If evidence confirms it is NOT a bug, keep it in `notBugs` with an updated, more definitive reason.

## MANDATORY: Factual Claims Require web_search

Any bug claim that depends on factual knowledge MUST be verified with `web_search` before being reported. Do NOT rely on your own knowledge — your training data may be outdated or incorrect.

Categories that MUST trigger web_search:
- **Version compatibility** — "library X version Y does/doesn't support feature Z"
- **Runtime support** — "platform X doesn't support runtime Y"
- **API behavior** — "this API returns X" or "this endpoint expects Y"
- **Deprecation claims** — "this method/feature was deprecated in version X"
- **Default values** — "the default for config option X is Y"
- **Breaking changes** — "upgrading from X to Y breaks Z"

If web search returns no evidence supporting the claim, move the bug to `notBugs` with reason "speculative".
